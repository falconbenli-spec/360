# RFP and Tender Response Checklist

Use for formal RFPs from government, semi-government, and large corporate buyers in Saudi Arabia and the GCC.

## Before deciding to bid

- [ ] Read the full tender document, including annexes and the draft contract
- [ ] Identify the scoring weights (technical % vs financial %) and the minimum technical score to pass
- [ ] List mandatory requirements; mark any the agency cannot meet
- [ ] Check eligibility: sector classification, minimum years, minimum similar projects, local content requirements
- [ ] Confirm the bid bond amount and that the bank can issue it in time
- [ ] Estimate the cost of responding; decide bid / no-bid with the agency lead

## Documents (keep current copies in a shared folder, check expiry dates)

- [ ] Commercial registration (السجل التجاري)
- [ ] VAT registration certificate
- [ ] Zakat and tax certificate (شهادة الزكاة والدخل)
- [ ] GOSI certificate (شهادة التأمينات الاجتماعية)
- [ ] Chamber of commerce membership
- [ ] Saudization / Nitaqat certificate
- [ ] Classification certificate if required for the category
- [ ] Bank letter or financial statements if requested
- [ ] Authorized signatory letter and ID
- [ ] Etimad registration confirmation (for government tenders)
- [ ] Previous contracts or completion certificates for similar work

## Etimad platform basics

- Government tenders are published and submitted on Etimad (منصة اعتماد). Verify the agency's registration is active and the authorized representative's access works before the deadline week.
- Tender documents usually carry a purchase fee; buy them early to read the full requirements.
- A bid bond (الضمان الابتدائي) is required with the bid; verify the percentage and the accepted bank format in the tender document.
- A performance bond (الضمان النهائي) is required after award.
- Clarification questions are submitted within a stated window; answers are shared with all bidders.
- Submission deadlines are enforced by the platform. Upload at least one day early.
- Verify the current rules in the tender itself; platform procedures change.

## Technical proposal structure (follow the tender's own numbering)

- [ ] Cover letter on letterhead, signed
- [ ] Compliance matrix: every requirement, where it is addressed, compliant / partial / alternative
- [ ] Company profile: history, services, team size, certifications
- [ ] Understanding of the requirement: restate their objectives in your words
- [ ] Methodology: phases, activities, deliverables, quality control
- [ ] Work plan and timeline: Gantt-style table with milestones
- [ ] Team: organization chart, CVs, roles, Saudi staff percentage
- [ ] Similar projects: three to five, each with client, scope, dates, value, reference contact
- [ ] Tools and technology
- [ ] Risk register and mitigation
- [ ] Local content statement where requested
- [ ] All mandatory annexes in the order requested

## Financial proposal (separate volume when required)

- [ ] Prices in the format and currency demanded (usually SAR, usually a bill of quantities)
- [ ] VAT shown separately
- [ ] Validity period as required
- [ ] No prices anywhere in the technical volume
- [ ] Assumptions and exclusions listed
- [ ] Payment schedule per the tender's terms

## Quality check before submission

- [ ] Every requirement in the compliance matrix has a page reference
- [ ] Page limits and formatting rules met
- [ ] Language matches the requirement (Arabic primary for most government tenders)
- [ ] Figures consistent between technical, financial, and cover letter
- [ ] Signed, stamped, and dated where required
- [ ] Someone who did not write it reads it against the scoring criteria
- [ ] Uploaded with time to spare; confirmation saved

## After submission

- [ ] Note the expected award date and the clarification window
- [ ] Prepare for a possible presentation or clarification round
- [ ] Log the tender, price, and outcome; request debrief scores if the tender allows
